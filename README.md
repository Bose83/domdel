# Дом вместе — приложение для Netlify

Мобильное веб-приложение для семьи или соседей. В этой версии есть настоящие личные аккаунты, серверная проверка прав и общая база PostgreSQL. Это исходный проект для публикации, а не один локальный HTML-файл.

## Самый короткий путь к запуску

1. Распакуйте архив. Создайте приватный репозиторий GitHub и загрузите в его корень **содержимое** папки `dom-vmeste-netlify`. Файлы `package.json` и `netlify.toml` должны находиться в корне репозитория.
2. В Netlify выберите **Add new project → Import an existing project**, подключите GitHub и выберите репозиторий.
3. Настройки уже записаны в `netlify.toml`: команда сборки `npm run build`, папка публикации `public`, серверные функции `netlify/functions`, Node.js 22. Не задавайте отдельный Base directory, если загрузили содержимое папки в корень.
4. Опубликуйте проект. Пакет `@netlify/database` и миграции в `netlify/database/migrations` рассчитаны на встроенный **Netlify Database**. Проверьте в **Data & Storage → Database**, что база создана и обе миграции применились. При необходимости создайте базу там и повторите deploy. Сведения о подключении Netlify передаёт функциям через свою среду; в браузере ключей базы нет.
5. Откройте полученный HTTPS-адрес. Создайте аккаунт: логин латиницей, имя и пароль от 12 символов. **Сохраните показанный код восстановления:** email не используется.
6. Создайте комнату. В разделе **Ещё → Семья и приглашения** скопируйте её код. Отправьте близким адрес сайта и этот код. Каждый создаёт свой аккаунт и отправляет заявку. Любой действующий участник семьи может её принять.
7. Для push выполните отдельный шаг ниже. Всё остальное работает без настройки push.

**Не загружайте только папку `public` через Netlify Drop:** такой способ не подготовит серверную часть и базу. Этот проект должен пройти сборку с исходниками.

Netlify Database доступен на тарифах с кредитами; использование функций, базы и трафика учитывается в лимитах аккаунта. Проект не подключает оплату автоматически и не меняет тариф. Проверьте доступность Database в своём аккаунте до приглашения семьи.

Официальные инструкции, сверенные при подготовке:
- https://docs.netlify.com/build/data-and-storage/netlify-database/getting-started/
- https://docs.netlify.com/build/data-and-storage/netlify-database/migrations/
- https://docs.netlify.com/build/functions/scheduled-functions/

## Запоминаемый вход

Сессия хранится в HttpOnly cookie; пароль приложение в браузере не сохраняет. Устройство остаётся авторизованным до 180 дней бездействия; при работе в комнате срок продлевается. После закрытия и открытия браузера повторно входить не требуется, если браузер не удалил cookie. Приватный режим и очистка данных браузера могут сбросить вход.

В настройках есть выход с этого устройства и выход со всех устройств. Восстановление по секретному коду меняет пароль, отзывает прежние сессии и выдаёт новый одноразовый код восстановления. Если потеряны и пароль, и код, автоматического восстановления без email нет.

## Что работает

- Создание комнаты и вступление по случайному коду из 10 символов с подтверждением любого участника. Код не заменяет личный вход.
- Один организатор — создатель комнаты. Изменить его роль или исключить голосованием нельзя.
- Голосование за исключение остальных: от трёх участников, две трети остальных голосов, срок 48 часов. При исключении открытые дела возвращаются в общий пул, код комнаты меняется.
- Дела, общий пул, помещения, редактируемые шаблоны и повторения, принятие назначений, обсуждение и передача задач.
- Сразу подходящее дело с кнопками «Беру» / «Другое дело», без вопроса о количестве свободного времени. Доступность можно изменить в свёрнутом блоке ниже.
- Автоматический подбор без внешней модели: ограничения участника, сложность, сроки, история замеров и нагрузка. Для распределения между всеми организатор открывает предложения и применяет их; участники принимают назначения.
- Отдельная редактируемая память каждой комнаты. Заметки сохраняются как договорённости; свободный текст не интерпретируется языковой моделью. Запреты указываются в профиле. Средняя длительность уточняется после двух измеренных выполнений одноимённого дела данным человеком.
- Таймеры, пауза, продление и завершение подхода. Долгие разборы можно выполнять по частям. Награда за подход не дублируется при завершении того же дела в тот же день.
- Личные звёзды, награды, согласование цели ребёнка, самооценка и семейный отзыв, история и итоги дня.
- Общий календарь, приглашённые участники события и ответы, чат, ответы на сообщения, обсуждение дел и событий.
- Импорт TXT/JSON с предварительным просмотром и готовым промптом для внешнего ИИ по желанию. Приложение само никуда заметки не отправляет. Импорт до 1 МБ и 200 записей; неизвестные поля отклоняются, команды не выполняются.
- Настройки уведомлений, тихие часы, звук таймера, отключение поздравлений и анимации.
- Экспорт данных своей комнаты организатором. Общие резервные копии базы — через Netlify Database.

## Ненавязчивые push

Push включаются только по нажатию пользователя. На каждом устройстве — отдельно. Без разрешения браузера запросы на показ не появляются. Есть режимы «Без напоминаний», «Только важное» и «Все напоминания», тихие часы по умолчанию 22:00–10:00.

Для владельца сайта:

```sh
npm ci
node scripts/push-keys.mjs
```

Команда выводит пару VAPID-ключей. Добавьте `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` в Netlify → Environment variables со scope **Functions** и выполните повторный deploy. Приватный ключ не помещайте в исходники. Netlify предоставляет переменную `URL` с адресом сайта; она используется как идентификатор отправителя. При собственном тестовом окружении её нужно задать явно.

После этого пользователь открывает **Настройки → Напоминания → Включить push на устройстве**. На iPhone сначала следует добавить сайт на экран «Домой» и открыть оттуда; поддержка зависит от версии системы. Кнопка отключения снимает подписку этого устройства. Выход из аккаунта отзывает серверную подписку вместе с сессией.

Функция `reminders` проверяет напоминания каждую минуту на опубликованном сайте. Она группирует события, таймеры, назначения и адресованные сообщения. Не чаще одного push за пять минут на устройство; уже отправленные напоминания не повторяются. Текст push не раскрывает переписку или названия задач на экране блокировки. По умолчанию обычные сообщения без упоминания/ответа не присылаются.

Push не является точным будильником: браузер, сеть и планировщик могут задержать доставку. Звук таймера при открытом приложении работает отдельно. В quiet hours приложение не отправляет push. Для первого релиза обработка ограничена 20 подписками за проход, с очередью по времени предыдущей проверки; это не проверенная на массовую нагрузку система уведомлений.

## Проверить локально

Требуется Node.js 22.13 или новее.

```sh
npm ci
npm test
npm run dev
```

Откройте `http://localhost:8888`. Локальная версия использует настоящий движок PostgreSQL через PGlite; данные сохраняются в `.local/postgres` и не отправляются на Netlify. Для проверки ролей создавайте отдельные аккаунты в разных браузерах/приватных окнах. Свободной подмены пользователя нет.

```sh
npm run check:functions
```

Эта команда упаковывает API и планировщик официальным упаковщиком Netlify без публикации. Автоматические проверки, их охват и ограничения описаны в `TEST-REPORT.md`.

## Данные, резервные копии и ограничения

- Для общей работы нужен интернет. Действия подтверждаются только сервером. Офлайн-очереди нет.
- Другие устройства опрашивают сервер раз в 20 секунд. Во время ввода форма автоматически не заменяется. При конфликте версий приложение просит обновить данные; введённый текст остаётся на экране до обновления.
- Часовой пояс комнаты в этом релизе — **Europe/Samara**. Это относится к срокам, календарю, дням начислений и тихим часам.
- Повторяющиеся дела создаются при открытии/действиях в комнате. Они не материализуются автоматически в полностью неактивной комнате.
- Один аккаунт состоит в одной комнате. Максимум 100 участников; защитный предел состояния комнаты — 8 МБ. Семейные данные не включены в архив.
- JSON-экспорт комнаты содержит личные данные и приглашение. Храните его приватно. Он нужен для архива и переноса данных, но не восстанавливает аккаунты и пароли. Полное восстановление выполняется средствами резервных копий Netlify Database. Не восстанавливайте старый локальный файл поверх опубликованной базы: он не содержит связей с личными аккаунтами.
- Раздел «История» сохраняет начисления и изменения. Отчёт по дню не является полной исторической копией всех просроченных задач на ту дату.
- Настоящего обучения языковой модели, распознавания голоса и подключения стороннего ИИ нет.

## Устройство проекта

`public/` — мобильный интерфейс и небольшой клиент, который передаёт действия серверу. `src/household.js` — существующие сценарии и генерация интерфейса, перенесённые на сервер. `server/engine.mjs` выполняет только этот фиксированный код в изолированном DOM и принимает лишь действия/поля, доступные текущему пользователю на серверном экране. Пользовательские файлы не исполняются. `server/household-source.mjs` генерируется при сборке; редактировать нужно `src/household.js`.

`server/api.mjs` отвечает за аккаунты, сессии, транзакции и доступ к комнате. Браузер не загружает полный снимок состояния обратно в базу. Комната блокируется на время изменения, версия защищает от устаревших действий, идентификатор запроса предотвращает повторное выполнение. UI-состояние хранится отдельно для каждой сессии; вкладки одного браузера используют одну сессию и могут попросить обновление при одновременной работе.

Пароли: scrypt с индивидуальной солью. Сессионные и восстановительные токены в базе хранятся как хеши. SQL-запросы параметризованы; есть серверные лимиты попыток входа/подбора кода, проверка Origin, лимиты размера импорта, экранирование текста и CSP. Проверки снижают риски, но не заменяют внешний аудит безопасности перед массовым запуском.
